# 模型评审清单

按用户的业务需求与访问模式评审，不机械要求所有表满足同一种范式。

1. 实体边界与粒度：一行代表什么，主键是否稳定，唯一性是否来自真实约束。
2. 字段设计：类型、长度、金额精度、时间与时区、NULL、默认值和枚举语义。
3. 关系：复合键列映射、外键约束、删除更新策略与历史保留要求。
4. 访问模式：已有查询、索引支持、JOIN 代价、读写比例与热点；缺少负载不能量化收益。
5. 演进：兼容旧应用的扩展/迁移/收缩步骤、数据回填、约束验证与恢复路径。
6. 业务知识缺失：保留期限、去重规则、指标口径和实体关系交由业务方确认。

交付问题、证据、候选设计、取舍、待确认项与迁移验证清单。候选 DDL 不执行，建议关系不写入真实 ER 声明关系图。破坏性变更不以反向 DDL 代替数据恢复方案。

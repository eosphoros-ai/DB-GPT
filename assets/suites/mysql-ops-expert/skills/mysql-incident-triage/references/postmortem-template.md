## 二、根因分析

| 层次 | 内容 |
|:---|:---|
| **直接原因** | `order_main` 查询 `WHERE status>0 AND gmt_create>?` 无可用复合索引，单次扫描 124 万行 |
| **促成因素** | 发布时段为业务高峰；连接池上限 800 使慢 SQL 迅速占满连接；无 SQL 上线前审查 |
| **根本原因** | 慢 SQL 在测试环境未暴露（测试库数据量 2000 行，量级差 600 倍），且发布流程无"新 SQL 需 DBA review"卡点 |
| **检测缺失** | 只有 CPU 阈值告警（滞后 8 min）；无 `Threads_running` / 扫描放大比告警 |
| **处置短板** | 值班第一轮 `KILL` 未同时限流来源，导致 5 min 内回灌 |

**5 Why 要求**：至少问到"流程/机制"层面。若最后一层答案是"某人选错了/没注意到"，说明根因还没找到。

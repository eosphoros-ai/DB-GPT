# MySQL 智能运维专家套件（MySQL Ops Expert）

面向 DBA 与后端/SRE 工程师的 MySQL 运维工具箱。把日常八大类工作——慢 SQL 诊断、实例巡检、线上故障应急、DDL 变更评审、备份与误删恢复、参数调优、运维汇报——收敛成 7 个可直接调用的技能，并由一个**共享知识库**统一判定口径：指标阈值基准、10 类故障的现象→根因决策树、按场景分组的只读诊断命令清单，以及命令风险分级（L0–L3）与安全红线。

套件的设计取向是**零配置可用**：所有技能都以"你贴诊断输出（`EXPLAIN`、`SHOW GLOBAL STATUS`、`SHOW ENGINE INNODB STATUS`、慢日志、监控导出）→ 出结构化结论"为主路径，不要求先接通数据库。同时每条建议都强制携带**依据数值、风险分级、回退命令**，避免"建议优化一下"这类无法落地、也无法验证的输出。

> **免责声明：** 本套件辅助数据库运维工作，不替代 DBA 判断与责任。所有变更类、恢复类、参数类建议在生产环境执行前，必须由具备权限与备份保障的人员复核确认；涉及数据覆盖或不可逆操作的步骤，需取得业务与管理层授权。输出中的阈值与耗时估算为通用经验值，请结合本地基线校准。

## 适用角色

- **DBA / 数据库运维** — 日常巡检、故障定位、变更评审、恢复方案的标准作业流程与报告产出，减少重复劳动并保证结论口径一致。
- **后端工程师 / 服务负责人** — 拿到 SQL 后能直接得到"扫描放大比、失效原因编号、改写 diff、预期收益区间"，而不是模糊的优化建议。
- **SRE / 技术管理者** — 通过运维报告与容量趋势获得可决策的量化结论（触顶日期、成本对比、需拍板事项）。

## 快捷调用

| 命令 | 说明 |
|:---|:---|
| `/SQL 体检` | 贴 SQL + `EXPLAIN`（可选建表语句、`SHOW INDEX`、慢日志）→ 归因 + 改写 + 索引方案 + 可验证预期 |
| `/实例巡检` | 说"帮我巡检"先拿采集脚本；贴回结果得到红黄绿分级报告与可认领问题清单 |
| `/故障应急` | 描述现象（如"主库 CPU 100%，大量超时"）→ 定级、保现场、止血动作（含回退）、复盘 |
| `/变更评审` | 贴 `ALTER`/订正 SQL/参数变更 → 在线能力与工具选型、空间与耗时估算、回滚方案、一票否决检查 |
| `/备份恢复` | 评估备份策略（RPO/RTO 实测口径）、误删数据找回、PITR、单表恢复 |
| `/参数调优` | 贴 `VARIABLES` + 两次 `STATUS` + 机器规格 → 内存总账校验 + 分改动组建议 + 明确不建议改的清单 |
| `/运维报告` | 说清类型（日报/周报/容量/向上汇报）→ 结论先行、量化、带跟进闭环的报告 |

## 技能

| 技能 | 说明 |
|:---|:---|
| **SQL 体检** | 以"扫描放大比"为核心量化锚点，逐条勾选 24 项索引失效原因（编号 I-01–I-24 可追溯）；解读 `EXPLAIN`/`FORMAT=TREE`/`EXPLAIN ANALYZE`，含 `key_len` 判联合索引断裂、`loops × actual time` 判真实代价；输出改写 diff、索引 DDL 与在线能力判断、预期效果区间与验收标准（放大比 ≤10、无 `Using temporary`）。 |
| **实例巡检** | 8 个域逐项判读（可用性/资源/连接/锁与事务/InnoDB 健康/复制/空间与对象/配置漂移），每条结论必须给实测值 + 阈值依据 + 影响 + 动作。附带可直接跑的采集脚本（两次采样算速率，避免累计值误判）。强调**趋势优先于瞬时值**与多实例**参数漂移矩阵**。 |
| **故障应急** | 按 T1–T10 决策树进入 10 类场景（CPU、连接、锁与死锁、整体变慢、单 SQL、IO、主从延迟、磁盘满、OOM、起不来）；固定"先保现场 → 再止血 → 后根治"顺序，每个止血动作携带前置检查/预估影响/观察指标/回退命令/不可逆点。含 MDL 阻塞、大事务回滚权衡、复制不一致校验等易错点处置。 |
| **变更评审** | 判定 `INSTANT`/`INPLACE`/`COPY` 可行性与耗时估算公式；gh-ost 与 pt-osc 逐项对比与命令骨架；空间峰值、binlog 产出、从库延迟、下游同步链路影响量化；**9 条一票否决清单**（无回滚方案、磁盘余量不足峰值、大表 COPY 直执主库等）；不可逆变更强制两阶段方案。 |
| **备份恢复** | 以"实际 RPO / 实测 RTO / 演练证据"三问评估备份链闭环（含"binlog 保留期 < 全备周期"这类致命组合）；误删找回按 6 种方式代价排序（未提交事务回滚 → 延迟从库 → binlog 闪回 → 临时实例部分回补），并明确"删后新数据保不保"必须由业务决策；PITR 分阶段命令与校验点、单表 `IMPORT TABLESPACE` 路径。 |
| **参数调优** | 先立目标（吞吐/低延迟/持久性）再调参；**内存总账校验为一票否决项**（BP + 每连接最坏内存 × `max_connections` 是否成立）；redo 容量与 checkpoint 年龄、双 1 基线不可默认牺牲、`innodb_io_capacity` 与实际盘能力匹配；8.0 特性与 5.7→8.0 行为差异；必含"明确不建议改的清单"及理由。 |
| **运维报告** | 按读者分层（日报/周报/容量/向上汇报/治理专项），结论先行、量化对比、变化优先于状态、容量必须给触顶日期与置信度、**上期承诺逐条闭环**；附 6 类反模式对照表（"整体平稳"该改写成什么）。 |
| MySQL 运维知识库（内部，不出现在菜单） | 指标绿/黄/红阈值基准（含 5.7 与 8.0 视图差异、云 RDS 受限说明）；现象→根因决策树；只读命令清单；命令 L0–L3 分级、六条硬红线（不猜数据、不默认改参数、主库不做重活、无备份不做恢复、不删文件、输出脱敏）。 |

**技能之间的衔接**：巡检产出的问题清单 → SQL 体检 / 参数调优 做归因 → 变更评审出可执行方案 → 故障应急负责止血 → 运维报告把闭环沉淀为下期承诺。报告与巡检的结论若冲突，以知识库阈值为准（通常是时间窗口差异）。

## Connectors（可选增强）

所有技能在**无连接器**时功能完整（贴输出即可用）。连上对应品类后减少人工搬运：

| 能做什么 | 无连接器时 | 连上后增强 |
|:---|:---|:---|
| 采集诊断数据 | 你执行命令并粘贴输出 | 数据库只读连接后自动采集，支持多实例批量巡检 |
| 趋势与容量判断 | 手工截图/导 CSV | 监控指标接入后自动算环比、斜率与触顶日期 |
| 报告与方案沉淀 | 落盘 Markdown | 文档平台/知识库自动发布归档，形成历史序列 |
| 问题清单跟进 | 表格可复制建单 | 任务工具批量建单、指派、超期提醒、状态回填下期报告 |
| 应急与播报 | 会话内输出 | 沟通工具推送"当前判定 + 待确认项"到应急群 |

钉钉（文档/待办/知识库/群消息）、飞书是当前应用内置支持的连接器，在设置里开启即可被上述技能直接使用；数据库与监控类连接需按你本地的方式接入。详见 [CONNECTORS.md](CONNECTORS.md)。

## 迭代建议

这套内容是**通用基线**，落地时最值得补的三样东西：① 你们的指标告警阈值与业务基线（替换知识库里的通用值）；② 内部变更规范与审批流（并入变更评审的一票否决清单）；③ 好的复盘范文与你们的报告版式（替换 `references/` 中的模板）。把它们放进对应技能的 `references/` 目录即可生效，无需改动主流程。

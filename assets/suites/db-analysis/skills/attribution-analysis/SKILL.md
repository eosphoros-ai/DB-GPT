# 归因分析（Attribution Analysis）

## 技能目标

回答"这个指标为什么变成这样"，并给出**可复核、可执行**的归因结论。

归因不是找故事，而是一套有纪律的计算与排除过程：

1. **确认异动是真的**（不是口径变更、数据延迟、日历效应造成的假异动）；
2. **量化各维度贡献度**（谁贡献了多少，用数字而不是形容词）；
3. **逐层下钻到可执行粒度**（渠道 → 品类 → 客户/门店 → SKU，停在"有人能采取行动"的那一层）；
4. **分离量与价、规模与结构**（是卖得少了，还是卖便宜了？是整体萎缩，还是结构迁移？）；
5. **区分事实与假设**（数据库能证明的写进结论，不能证明的写进待验证假设）。

产物是 `conclusion_card`（归因结论卡）+ 支撑图表，随后由 `report-generation` 装配进报告。

## 核心工作流程

1. **定义异动与基线**
   - 明确指标（含 pin 版本）、范围、本期窗口、对比窗口（环比 + 同比，**等长**）。
   - 计算变动绝对额与百分比；判断是否构成"异动"：常用阈值为环比 |Δ| ≥ 5% 或超出近 8 周波动的 2 倍标准差。未达阈值时如实说明"属正常波动"，不要强行归因。
   - 用 `semantic_search(query="<指标名> 口径变更 规则", types=["rule","metric"], top_k=5)` 检查该指标近期是否有口径/版本变更，避免把口径变更当业务下滑。

2. **数据可信度排除（先排假异动）**
   - **完整性**：本期最后一天数据是否已完整入仓（数据截止时间 vs 当前时间）；是否有分区/日期缺数。
   - **日历效应**：本期与对比期的工作日数、节假日、大促日是否可比（如本期含国庆假期、上期不含）。
   - **口径变更**：默认过滤是否变化、行级权限是否收窄、新增/下线渠道或品类导致枚举不可比。
   - **退款/取消**：`valid_gmv` 类指标是否受退款率异常影响（取 `refund_rate` 同期对比）。
   - 任一排除项成立 → 先修正对比口径（等长窗口、剔除节假日、补数据）再重新计算，并在报告中标注。

3. **一级维度贡献度拆解（加法型指标）**
   - 取数：`nl2sql(question="<范围> 本期与对比期按<维度>汇总<指标>及差额", dataset_id=..., metric_refs=[...同版本...], grain=..., sql_only=true)` → `sql_execute(...)`。
   - 计算贡献度：`贡献度_i = Δ_i / Δ_total`（Δ 为差额，负值代表下滑）。
   - **闭合校验**：`Σ Δ_i` 必须等于 `Δ_total`，差值 > 2% 说明有维度未覆盖（归入"其他"并标注占比）或存在重复计数（1:N join 放大）。
   - 排序取主因（贡献度 ≥ 40% 或显著高于第二名）与次因，剩余归为"长尾"。

4. **逐层下钻（停止条件明确）**
   - 对主因维度做二级拆解（渠道 → 品类 → 客户/门店 → SKU），每层都重算贡献度与闭合校验。
   - **停止条件**（满足任一即停）：① 已下钻到可执行粒度（有明确责任方能采取行动）；② 该层主因贡献度 < 40% 且分布均匀（说明是普遍性下滑，不是结构性问题）；③ 下钻层样本量 < 30（统计意义不足，标注低置信度）；④ 已达步数上限。
   - 每层产出一张图（贡献度条形图 / 结构堆叠图），交给 `chart-advisor` 选型。

5. **量价分解与结构效应分离**
   - 量价分解（`指标 = 量 × 价`，如 `valid_gmv = paid_order_cnt × aov`）：
     - 量效应 `= ΔQ × P0`
     - 价效应 `= ΔP × Q1`
     - 校验：量效应 + 价效应 ≈ ΔGMV（误差 > 1% 需检查是否混用了不同版本指标）
   - 结构效应（mix shift）：分别计算"各部分自身增速"与"各部分占比变化"，判断总量变化来自内部萎缩还是结构迁移（如高毛利品类占比下降会拉低整体客单价，但各品类客单价可能都在涨）。
   - 结论表述要区分："量的问题"（拉新/转化/流量）与"价的问题"（折扣/结构/促销），二者对应完全不同的建议动作。

6. **异动起点与影响范围定位**
   - 日粒度看断点：找出开始偏离基线的具体日期，检查该日期前后是否有可查的系统性变化（活动结束、价格调整、库存缺货、页面改版记录）。
   - 范围界定：确认异动是否仅限某渠道/品类/区域/客户群（"仅自营App 3C、仅华东"比"整体下滑"信息量大得多，也更能指向可执行动作）。
   - 数据库内无佐证的外部因素（竞品促销、宏观、天气）→ **只能写进待验证假设**，并说明需要哪些外部数据来验证。

7. **产出归因结论卡**
   - 结构：`结论（一句话）→ 量化归因（主因 x% / 次因 y% / 长尾 z%）→ 证据（图表 id + 关键数字 + 步骤号）→ 口径（指标@版本 + 窗口）→ 置信度（高/中/低）→ 待验证假设 → 建议动作`。
   - 置信度判定：单维直接读出且闭合 = 高；多维交叉、样本充足、已排除假异动 = 中；样本 < 30 / 口径有例外 / 依赖假设 = 低（必须在报告标注）。
   - 建议动作必须可执行、可归属、可复盘：写清"谁做、做什么、看哪个指标、多久复盘"。

## 完整流程示例

承接 `multi-step-analysis`：数据集 `ds-trade-east-1024`，`valid_gmv@v2` / `paid_order_cnt@v1` / `aov@v1` / `refund_rate@v1`，日粒度，窗口 2026-10-01~10-24 vs 2026-09-01~09-24 vs 2025-10-01~10-24。

Step 1（异动确认）
  本期 1.82 亿 / 上月同期 2.075 亿 → ΔGMV = -0.255 亿，环比 -12.3%（超过 5% 阈值，构成异动）
  同比：去年同期 1.898 亿 → -4.1%（说明本月环比下滑幅度显著大于长期趋势）

  → valid_gmv 最近一次变更为 v2（2026-07 生效），本期与对比期同版本 → 非口径变更导致 ✅

## 注意事项

- **先排假异动再归因**：口径变更、数据未完整入仓、日历效应（工作日数/节假日）、行级权限收窄都会制造"假下滑"。跳过这一步的归因结论几乎必然误导决策。
- **贡献度必须闭合**：各维度差额之和与总差额的偏差 > 2% 时，先查未覆盖枚举（归"其他"）与 1:N join 重复计数，再继续下钻。不闭合的贡献度不可写入报告。
- **等长窗口是硬要求**：本月至今 vs 上月整月会虚高下滑幅度；本期含节假日要补一版"剔除节假日"口径并双写说明。
- **区分量与价、规模与结构**：不要把"客单价下降"与"高客单品类占比下降"混为一谈（后者是结构效应，各品类客单价可能都在涨）。
- **相关不等于因果**：数据库只能给出"同时发生"。凡涉及外部原因（竞品、宏观、天气、舆情）一律进"待验证假设"，并写清需要什么数据才能验证。
- **禁止臆测与夸大**：不写"大幅""显著"而不给数字；不写未经计算的百分比；不把低置信度结论表述为确定性结论。
- **样本量与置信度**：下钻层样本 < 30 时标注低置信度，避免用个别大客户/单店波动解释整体变化。
- **不要为了凑主因而过度下钻**：当各维度分布均匀（无一项 ≥ 40%）时，正确结论是"普遍性下滑"，应转向宏观/流量层面解释，而不是硬指一个维度。
- **步数与代价控制**：归因下钻容易发散，遵守套件 `max_steps=8`；`est_scan_gb > 100` 会触发审批 confirm，先缩小窗口或降粒度。
- **每层结论都要能指回图表与 SQL 步骤号**，这是报告引用 chips 与可复现性的基础。
- 工具只使用套件 `tools.allow` 内的：`semantic_search`（口径/规则/样例核查）、`nl2sql`、`sql_execute`、`chart`（贡献度图）；结论卡通过 `report_export` 的 `sections` 落地。

# 健康巡检技能 (Health Inspection)

本技能是 `db-ops`（智能运维）套件的例行体检能力，回答"这个库现在健康吗、哪里在恶化、多久会出事"。它是**只读技能**：只采集、只判读、只出报告与整改建议，不触发任何 DDL/ANALYZE。可挂到定时任务模块做周期化巡检。

## 技能目标

1. 对指定目标库在指定时间窗内建立**多维基线**，覆盖六大类指标（连接/QPS、慢查询、缓冲池、磁盘、复制、锁）。
2. 用**三级判据**给出健康度：绝对阈值、相对基线偏离、趋势斜率（容量类必须给"按当前增速预计 N 天后触顶"）。
3. 产出结构化巡检报告：健康分 + 分项明细 + 异常清单（P0/P1/P2）+ 整改建议（标注是否需审批）。
4. 与慢查询诊断解耦：巡检发现的慢查询线索**移交** `slow-query-diagnosis` 深挖，不在巡检里做根因定位。

## 前置条件

- `target_db` 已绑定；多实例巡检需逐个绑定，**不得**一次跨库全扫。
- `time_window` 已绑定并转为绝对区间；例行巡检推荐"最近 24h + 同比上周同时段"两段，便于识别周期性波动。
- `env` 可读；生产库巡检优先走只读从库采集，避免巡检本身增加主库压力。

## 核心工作流程

### 1. 采集多维指标（一次拿全，避免多次往返）
调用 `db_metrics`，传参：
- `target_db`、`time_window`（绝对区间）、`granularity`（24h 窗建议 `5m`，7 天窗建议 `1h`）；
- `metrics`：至少覆盖下表六类；
- `compare`（可选）：`{baseline: "previous_period"}` 或同比上周同时段，用于计算偏离度；
- `aggregate`：`[avg, p95, max]` —— **只看均值会漏掉毛刺，必须有 p95/max**。

拿结果：每个指标的 `avg / p95 / max / 当前值 / 基线值 / 偏离百分比 / 趋势斜率`。

### 2. 六大类指标判读表（阈值可按企业标准覆盖，取"更严"的一侧）

| 类别 | 指标 | 健康 | 关注(P2) | 告警(P1) | 严重(P0) | 常见成因与整改方向 |
|---|---|---|---|---|---|---|
| 连接与吞吐 | 连接数使用率 | <60% | 60-75% | 75-90% | >90% 或出现拒绝连接 | 连接泄漏/池配置过小/慢查询堆积 → 查应用连接池、杀长事务（需审批） |
| 连接与吞吐 | QPS/TPS 突增倍数 | <1.5× 基线 | 1.5-2.5× | 2.5-5× | >5× | 批量任务/活动/爬虫 → 限流、错峰、读写分离 |
| 慢查询 | 慢查询率 | <0.5% | 0.5-2% | 2-5% | >5% | 缺索引/坏计划 → 移交 slow-query-diagnosis |
| 慢查询 | 最慢语句耗时 | <1s | 1-3s | 3-10s | >10s | 同上；关注是否长事务阻塞 |
| 缓冲池/内存 | 缓冲池命中率 | >99% | 97-99% | 90-97% | <90% | 大扫描冲刷/内存不足 → 定位大扫描 SQL、评估 buffer pool 扩容（配置变更需审批） |
| 缓冲池/内存 | 临时表落盘比例 | <10% | 10-25% | 25-50% | >50% | 排序/分组无索引、tmp_table_size 偏小 |
| 磁盘 | 空间使用率 | <70% | 70-80% | 80-90% | >90% | 数据增长/日志未清/大表无归档 → 移交 profile-governance；**必须给触顶天数预估** |
| 磁盘 | IO 利用率 / await | util<70% | 70-85% | 85-95% | >95% 或 await 显著上升 | 大扫描、备份窗口重叠、刷脏页抖动 |
| 复制 | 复制延迟 | <5s | 5-30s | 30-120s | >120s 或复制中断 | 大事务/DDL/单线程回放 → 查大事务、评估并行回放参数（需审批） |
| 锁与事务 | 锁等待/死锁次数 | 0 死锁 | 偶发锁等待 | 频繁锁等待 | 死锁频发或长事务 >60s | 事务过大、隔离级别、缺索引导致锁范围扩大 |
| 可用性 | 主库可连通性/重启次数 | 正常 | — | 单次异常重启 | 不可连通 | 立即上报，超出本技能范围 |

### 3. 趋势与容量外推（巡检的差异化价值）
- 对**容量类**指标（磁盘空间、表体积、连接数峰值、日志量）用时间窗内的斜率做线性外推，输出"按当前增速，预计 N 天后达到告警线 / M 天后触顶"。
- 斜率计算只用采集到的点位，**不外推超过 90 天**；数据点不足 3 个时标注"样本不足，趋势不可信"。
- 对**波动类**指标（QPS、慢查询率）标注周期性（是否每天固定时段峰值），避免把例行批量任务误报为异常。

### 4. 异常清单与整改建议分级
每条异常必须写全：`指标 / 当前值 / 判据（阈值或偏离度）/ 分级(P0-P2) / 证据时间点 / 影响 / 建议动作 / 动作类型(只读排查·配置变更·结构变更) / 是否需审批`。
- **只读排查类**（继续观察、缩窗复采、移交慢查询诊断）→ 无需审批，可直接建议。
- **配置/结构变更类**（扩内存、清归档、加索引、`ANALYZE`）→ 一律标"需审批"，生产环境 DDL 标"生产 deny，走变更流程"，转 `safe-ddl-review` 出正式提案。
- 严禁在巡检报告里写"已执行 XXX"—— 巡检不执行任何动作。

### 5. 产出巡检报告
输出 `diag_report`（巡检形态），结构固定：
1. **健康分与结论**（0-100 分：P0 每项 -20、P1 每项 -8、P2 每项 -2；给一句话结论，如"整体健康，磁盘容量为唯一 P1 风险"）；
2. **分项明细表**（六大类 × 指标 × avg/p95/max × 判据 × 状态灯）；
3. **异常清单**（按分级排序，含证据时间点）；
4. **趋势与容量外推**（含触顶天数）；
5. **整改建议与优先级路线图**（本周做 / 本月做 / 观察项，每条标是否需审批）；
6. **采集元信息**（`citation`：目标库、时间窗、粒度、采集节点是主库还是只读从库、缺失维度、语义层是否降级）。

若发现慢查询线索，附一行"移交建议：对 `<指纹>` 运行慢查询诊断（`/slowlog`）"。
最后调用 `terminate` 返回 1-2 句摘要（健康分 + 最高分级异常 + 最紧急一条建议）。

## 完整流程示例

```
问题：生产库 orders_prod 健康巡检出报告（时间窗：最近 24h，同比上周同时段）

Step 1: db_metrics(target_db="orders_prod",
                   time_window="2026-10-21T10:00:00+08:00/2026-10-22T10:00:00+08:00",
                   granularity="5m",
                   metrics=[connections_usage, qps, tps, slow_query_rate, slowest_statement_ms,
                            buffer_pool_hit_ratio, tmp_table_on_disk_ratio, disk_usage, disk_io_util,
                            replication_lag, lock_waits, deadlocks, long_transactions],
                   aggregate=[avg,p95,max],
                   compare={baseline: "previous_period"})
  → 连接数使用率 avg 42% / p95 71% / max 78%（基线 38%/62%/70%，+9% 偏离）
    QPS avg 1,750 / max 4,600（每天 23:10 固定峰值 → 周期性，非异常）
    慢查询率 avg 1.9% / p95 6.8%（超 P1 阈值 2%）
    缓冲池命中率 avg 96.4% / min 91.4%（P1）
    磁盘使用率 84.2%（P1），24h 内 +0.9%
    复制延迟 avg 3s / max 42s（max 落 P1）
    死锁 0，长事务 2 次（最长 78s，P2）

Step 2:（判读，不调工具）按阈值表定级 → P1×4（慢查询率、缓冲池、磁盘、复制延迟峰值）、P2×2（连接使用率 p95、长事务）

Step 3:（趋势外推）磁盘 24h +0.9% ⇒ 线性外推 ~18 天后达 90% 告警线、~50 天后触顶；
        标注"样本 24h，外推仅供参考，建议取 7 天窗复核"

Step 4: 异常清单与整改建议
  [P1] 慢查询率 p95 6.8%（23:10-00:30）→ 移交 slow-query-diagnosis 深挖（只读，无需审批）
  [P1] 缓冲池命中率最低 91.4%，与上述时段重合 → 疑大扫描冲刷，随慢查询结论一并处置（只读排查）
  [P1] 磁盘 84.2%，18 天后达告警线 → 移交 profile-governance 做膨胀/碎片/冷热分层与归档方案（结构变更需审批，生产 DDL deny）
  [P1] 复制延迟峰值 42s，落在批量任务窗口 → 排查大事务；并行回放参数调整属配置变更，需审批
  [P2] 连接使用率 p95 71% → 观察 + 核对应用连接池上限，暂不变更
  [P2] 长事务 78s ×2 → 定位发起方，建议应用侧拆批（无需 DB 变更）

Step 5: 产出 diag_report（健康分 100 - 4×8 - 2×2 = 64，结论"亚健康：慢查询与磁盘容量为两大主险"）
        + citation（采集自只读从库 rs-02；粒度 5m；缺失维度：无；语义层：降级 DBSummary，血缘未使用）
  terminate(result="orders_prod 巡检健康分 64（亚健康）：P1 风险 4 项，最紧急为磁盘 84.2%（约 18 天达告警线）与慢查询率 p95 6.8%；全部为建议，未执行任何变更。")
```

## 注意事项（含安全红线）

- **本技能全程只读**：只调 `db_metrics`（必要时 `slow_log` 取最慢语句样本、`semantic_search` 查表的业务重要性）。**不调用 `ddl`，不调用 `analyze`**；巡检中发现需要变更的项，只写建议并转交 `safe-ddl-review`。
- **巡检不得加压**：粒度与窗口要匹配（24h→5m、7d→1h），避免高频采集压垮目标库；生产优先走只读从库，采集自主库时在报告标注。
- **均值会骗人**：必须同时看 `p95` 与 `max`；周期性峰值（每天固定时段的批量任务）要标注为"周期性"，不重复告警。
- **阈值来源要可追溯**：报告里写明用的是套件默认阈值还是企业自定义阈值；两者冲突时**取更严的一侧**（与"策略只能加严"一致）。
- **容量类必须给时间维度**：只说"磁盘 84%"没有行动价值，要给"约 18 天后达告警线"。外推样本不足时明确标注不可信。
- **不越界**：实例不可连通、主库宕机、数据损坏等属事故响应，超出巡检范围 —— 立即上报并提示走应急流程，不要试图在本技能内处置。
- **不编数据**：某维度采集失败就在报告里标"缺失维度"，并说明对结论的影响；不得用历史值或估计值填充。
- **工具连续 2 次同类失败**即停止重试，向用户说明并请求授权或补充信息。
- 工具白名单以套件 `tools.allow` 为准；**无 `shell`**，不得用命令行绕过工具采集指标。

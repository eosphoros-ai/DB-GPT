# 法律专家套件工作流

## 总原则

1. 先受理、再检索、后结论、最后成文。禁止跳过事实梳理直接给法律结论。
2. 任何法条、案例、程序期限的表述都必须有来源；没有来源就写「未核验」，不猜条号。
3. 每份产出结尾都带免责与人工复核提示。
4. 未知信息用 [[待补充]] 占位，不推测当事人、金额、日期。
5. 结论要落到「谁、在什么期限内、做什么」，不交付只有分析没有动作的文档。

## 步骤

### 第 1 步：受理与事实梳理（skills/legal-intake）

- 触发：用户提出任何法务需求，都先跑这一步。
- 动作：确认委托立场、事项类型、相对方、时间线、诉求、期限压力、已有材料；把事实分成已证实 / 用户陈述 / 待核实三层。
- 产出：事实与争点摘要表 + 缺失信息清单。
- 完成条件：主体、时间、行为、结果四要素齐备，或已明确标注 [[待补充]]；每个争点都可判断。

### 第 2 步：依据检索与核验（skills/legal-research）

- 触发：需要法律依据支撑争点结论时。
- 动作：把争点转成检索问题 → web_search 找候选 → web_fetch 读原文 → 摘录条文 → 核验效力状态与生效时间。
- 产出：法律依据表（编号、法律名称、条号、原文摘录、来源 URL、核查日期、效力状态）。
- 完成条件：表中每条都带来源，或明确标记「未核验」；结论段引用的依据编号都能在表中找到。

### 第 3 步：实体分析（按事项类型二选一，可并行）

- 交易/文本类 → skills/contract-review：输出 P0-P3 分级风险清单、缺失条款检查、可直接替换的修改建议文本。
- 争议/纠纷类 → skills/dispute-strategy：输出请求权基础、构成要件核对、时效与管辖核查、多路径对比矩阵、证据清单与行动时间表。
- 完成条件：每个风险或结论都指向第 2 步的依据编号；P0 项必须给出明确处置动作。

### 第 4 步：成文（skills/legal-drafting）

- 触发：用户需要对外文书或内部意见书。
- 动作：按对应文书模板组装事实、依据、请求与期限，保留占位符，附证据与附件清单。
- 完成条件：文书要件齐全、无编造信息、附复核清单与签发前检查项。

### 第 5 步：汇总交付

用 generate_report 生成一份 Markdown 或 HTML 交付文档，固定包含：

1. 需求与委托立场
2. 事实与争点
3. 法律依据表
4. 分析与风险分级
5. 建议动作与时间表
6. 未解决问题与升级建议
7. 免责声明

## 完成判定

全部满足才算完成：

- 事实层：主体、时间、行为、结果四要素齐备或已标注缺失。
- 依据层：结论性陈述都有依据编号，或标注未核验并说明为何无法核验。
- 结论层：风险分级、责任主体、下一步动作、时间节点四件事都有。
- 交付层：含免责声明与执业律师复核提示。

## 熔断与升级

出现以下任一情形，停止自动结论，输出「需人工介入」说明与建议动作：

- 涉及刑事罪名认定、刑事报案、行政处罚应对；
- 涉及人身安全、劳动群体争议、舆情事件、监管问询；
- 需要签署对外正式法律意见、需要向法院或仲裁机构提交材料；
- 关键事实互相矛盾且无法从现有材料消解；
- 结论完全依赖某条无法核验的规定。

详细阈值见 references/risk-rating.md。

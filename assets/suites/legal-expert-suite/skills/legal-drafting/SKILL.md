# 法律文书起草

## 何时使用

事实与依据已经梳理清楚，需要产出对外或对内文本时：律师函、催款函、解除通知、法律意见书、起诉状要点、答辩要点、和解方案要点。

## 输入要求

- 文书类型与收件对象。
- 当事人信息：全称、统一社会信用代码或身份信息、地址、联系方式（缺项用 [[待补充]]）。
- 事实底稿（来自 /案情梳理，仅用「已证实」部分）。
- 依据表（来自 /法规检索，带编号与条文原文）。
- 诉求与履行期限，以及逾期后的下一步。
- 送达方式与证据留存要求。

## 步骤

1. 选模板：按下文「文书模板」确定结构，先搭骨架再填内容。
2. 写事实段：一段一个事实，只写有证据支撑的内容，按时间顺序排列；无证据的事实不写进对外文书。
3. 写依据段：引用依据表编号与条文原文，条文原文必须来自核验过的来源，未核验的注明「待核验」并不作为唯一支撑。
4. 写请求段：数量化、可执行、有明确期限（写具体日期或「自收到本函之日起 X 日内」），并写清逾期后果。
5. 处理占位符：缺失信息一律 [[待补充]]，并在文末「待补充清单」中汇总，禁止编造名称、金额、日期。
6. 一致性校验：金额小写与大写一致、当事人全称前后一致、日期格式统一（YYYY 年 MM 月 DD 日）、附件编号连续。
7. 列附件与证据清单：逐项编号，注明证明目的。
8. 出签发前检查清单：谁签、是否盖章、是否需要授权文件、送达方式与留痕。
9. 附免责声明与复核提示。

## 文书模板

### 律师函 / 催告函

1. 标题与编号、日期
2. 致送对象全称与地址
3. 事由（一句话）
4. 事实陈述（分段、按时间）
5. 法律依据（条号 + 原文摘录 + 依据编号）
6. 要求与履行期限
7. 逾期后果告知
8. 权利保留声明
9. 落款、联系人、联系方式
10. 附件清单

### 法律意见书

1. 委托事项与审查范围（明确不涵盖什么）
2. 假设与限制（材料真实性、未做尽调等）
3. 事实摘要
4. 法律分析（分问题逐项论证）
5. 结论（可操作、含条件）
6. 风险提示与不确定性说明
7. 免责与签署栏

### 起诉状要点

1. 当事人信息（原被告）
2. 诉讼请求（分项、金额、利息计算方式与起止日）
3. 事实与理由（分节论证，每节对应一个要件）
4. 管辖说明（依据条款 + 依据编号）
5. 证据清单与证明目的
6. 附件与份数说明

### 解除通知 / 终止通知

1. 通知依据（合同条款 + 法定依据编号）
2. 解除事由与事实
3. 解除生效时点
4. 结算与返还安排
5. 异议渠道与期限
6. 送达与留痕要求

## 产物格式

```markdown
## 文书正文
（按模板结构输出的完整初稿）

## 待补充清单
| 编号 | 占位内容 | 位置 | 补充责任人 |

## 附件与证据清单
| 编号 | 名称 | 证明目的 |

## 签发前检查清单
- [ ] 当事人全称与登记信息一致
- [ ] 金额大小写一致
- [ ] 依据已核验并标注编号
- [ ] 履行期限已写明具体日期或计算方式
- [ ] 送达方式与留痕已确认
- [ ] 已获授权签署

## 免责提示
```

## 质量检查

- 文书要件齐全，模板中每一节都有内容或明确写「不适用」。
- 事实段没有出现未证实内容，也没有把推测写成陈述。
- 引用的条文原文与依据表一致，编号可追溯。
- 请求事项可执行、有期限、有后果。
- 全文无编造的名称、金额、日期、案号。
- 待补充清单与实际占位符一一对应，数量一致。

## 失败处理

- 依据未核验：文书可生成，但正文中相关论述标注「（依据待核验）」，并在检查清单中置顶提醒。
- 关键当事人信息缺失：保留 [[待补充]] 并说明对外发送前必须补齐，不能先发后补。
- 用户要求写成确定结论（如「此案必胜」）：拒绝该表述，改为区间判断，并说明理由。
- 用户要求直接对外签发：说明本套件只出初稿，需执业律师复核签章，可提供复核要点清单。

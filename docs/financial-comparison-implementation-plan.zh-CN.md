## 1. 目标与范围

### 1.1 最终用户体验

用户在当前对话上传多份财报并明确提出对比要求，系统识别文件、公司、期间和口径，生成可追溯的对比报告，展示在现有右侧报告工作区。

每个关键数值都可以查看原文，每个差额都可以查看比较双方和公式。用户可以追问、恢复中断任务、重做某个专题和导出报告。

同时保留 `/financial-analysis` 独立页面的创建与查看能力。

### 1.2 第一版范围

| 项目 | 约定 |
| --- | --- |
| 文件数量 | 每次 2～5 份 PDF，限制可配置 |
| 横向对比 | 同年度、多公司；明确基准公司 |
| 跨年对比 | 同一公司、多年度；明确期间、取数政策和比较关系 |
| 输入支持 | 沿用当前中文、人民币、非金融企业、文本型年度报告 PDF 范围 |
| 计算 | 后端确定性计算，模型解释已有事实与计算 |
| 报告形式 | 现有报告工作区增加对比模式 |
| 导出 | JSON 与离线 HTML |
| 部分失败 | 保留成功文件、有效计算和已通过结论，说明相关缺口 |

暂不实现：自动汇率换算、扫描件 OCR、季报与年报混比、金融企业专用指标、综合投资评分、自动联网补数、生产级分布式任务队列。

上传多份文件不自动等同于要求比较。普通单财报分析、附件选择和其他聊天行为保持原有语义。

### 1.3 不可违反的业务约束

- 不补零、不伪造数据、不编造变化原因。
- 不混用合并与母公司报表、归母与整体利润、时点余额与期间累计值。
- 数值可读取不代表可以比较；可比性与数据提取状态分别表达。
- 指标高低不自动等同于企业优劣。
- 单位可以在确认币种和口径后统一；不暗中进行币种换算。
- 模型失败不应抹掉已保存事实与确定性计算。
- 内部专题任务状态放在执行过程，报告正文保持现有章节组织。
- 数据缺口、冲突与解释限制显示在对应章节，不用笼统成功状态掩盖。
- 不把所有 PDF 文本直接拼成一个模型提示词，也不要求先生成每家完整文字报告再二次总结。

## 4. T0：协议、状态与兼容设计

### 协议原则

旧报告保持 `schemaVersion: 1`、`mode: 'report'`，新增对比报告使用 `schemaVersion: 2`、`mode: 'comparison'`。

```ts
type FinancialReportData = ReportData | ComparisonReportData;
```

使用可区分联合类型。不要把多家公司塞进旧的 `report.companyName`，不要依赖无约束的 `any` 或大量类型断言绕过兼容问题。

| 对象 | 关键字段 |
| --- | --- |
| Comparison | 模式、标题、对象列表、期间、基准对象、取数政策版本 |
| Entity | 稳定任务内 ID、公司名称、识别依据、身份歧义状态 |
| Document | 文档 ID、文件 ID、SHA-256、公司、报告年度、提取器版本 |
| Fact | 公司、来源文档、指标、期间类型、期间范围或时点、口径、归属、币种、单位、原值、标准化值 |
| ComparisonCell | 公司、期间、指标、选定事实或计算、候选来源、选择原因 |
| Calculation | 唯一 ID、类型、输入引用、公式、精确结果、单位、不可用原因 |
| Finding | 涉及公司、期间、指标、比较方向、引用、支持状态 |
| Run | 创建、执行阶段、数据就绪、分析状态、发布状态 |

具体要求：

- 公司身份和文档身份分开；文档哈希不是公司 ID。
- 保留真实来源事实，不通过修改原始事实来消除冲突。
- 数据状态至少区分可用、缺失、冲突和提取失败。
- 可比性另外表达，包含规则与原因；不要把它与上述状态混成一个含义不清的枚举。
- 金额和精确结果使用 Decimal 对应的十进制字符串，不经过 float 再做业务计算。
- 引用使用唯一内部 ID；E1、E2 等仅作展示标签。
- ID 格式遵守现有引用解析器的长度与字符约束，必要时同步扩展并测试解析器。
- 取数规则、公式版本、输入来源和基准配置可追溯。
- 明确数据就绪、分析完成与报告发布三种不同语义。

### 验收

- 同公司跨年、不同公司同年、重复披露、缺失与冲突都有有效协议样例。
- 旧单报告不需要重算或重写才能打开。
- 前后端共享相同的状态含义和字段约束。

- 重试和恢复不重复解析成功文件。
- 低线程数与低并发配置下没有死锁。

## 7. T3：口径对齐、身份归属与候选事实选择

状态：工程实现与隔离测试完成（2026-10-24）；真实验收范围见第 16 节。依赖：T0；集成依赖 T2。

### 改动建议

- 新增 `comparison_alignment.py`。
- 规则输入为结构化提取结果，不依赖模型自由文本判断。

### 处理顺序

1. 识别实体、报告年度与事实实际期间。
2. 按公司、指标、期间、币种、口径和归属建立候选集合。
3. 选择单元格来源，保留所有候选与选择原因。
4. 检查比较双方可比性。
5. 输出矩阵与缺失、冲突、不可比原因。

### 规则

| 情况 | 行为 |
| --- | --- |
| 元、万元、亿元 | 确认币种和口径后统一，保留原值与原单位 |
| 合并和母公司 | 不自动混比 |
| 归母净利润和整体净利润 | 保持不同归属 |
| 期末余额和全年累计 | 区分时点与期间，不根据年份标签直接等同 |
| 同公司同年度重复披露 | 保留所有来源，使用可审计选择政策 |
| 明确重述 | 依据重述关系及比较政策选择，标注来源 |
| 未解释冲突 | 不静默采用最新文件或第一个值 |
| 公司身份或期间不明 | 返回具体待澄清项 |
| 财务定义可比但业务结构不同 | 允许数据展示，明确解释限制，不自动宣称同行可比 |

跨年模式不得简单按“每年最新披露”拼接趋势。逐个比较关系检查重述基础；无法形成一致序列时保留断点，不伪造连续趋势。

### 验收

- 规则结果确定、可重复。
- 每个选定值可追溯到候选集合和政策版本。
- 不同公司相同年份的事实不覆盖。
- 重述和未解释冲突分别处理。

## 8. T4：确定性计算与数据报告

状态：工程实现与隔离测试完成（2026-10-24）；真实验收范围见第 16 节。依赖：T3；集成依赖 T2。

### 改动建议

- 新增 `comparison_calculations.py`、`comparison_report.py`。
- 对现有 `calculations.py` 仅做必要的公共能力抽取。
- 不把所有公司的 facts 直接传入当前以指标、年份为键的计算函数。

### 第一版指标

- 营业收入、归母净利润、扣非归母净利润、经营现金流。
- 毛利率、费用率、现金利润比、资产负债率。
- 相对基准公司的金额差额。
- 比率之间的百分点差异。
- 跨年绝对变化、具备有效基数时的同比。

### 计算要求

- 单公司指标先在独立合法事实集合内计算，再生成跨对象计算。
- 零分母、缺失输入、冲突、口径不一致时返回明确原因。
- 负基数记录公式和解释边界，不把负数当缺失。
- 所有比较记录方向和双方角色，不能仅凭输入数组顺序让前端猜测。
- 不可比项不进入差值或排名。
- 图表和 UI 不能自行重算业务结果。
- 首选保持到原始事实的完整溯源。若引入计算依赖计算，必须实现递归展开、循环检测和依赖缺失处理。
- 数据报告在模型分析前持久化，模型失败时仍可读取。

### 验收

- 差值与百分点结果经过独立期望值验证。
- 每个结果能定位双方输入与原文。
- 重复指标、相同期间不产生 ID 冲突。
- 缺失或冲突不出现在曲线上作为零点。

- 未预计算的问题不允许模型心算新数值；明确缺口，或经受控计算流程产生新版本后再回答。

- 引用正确但公司或方向错误的结构化结论被拒绝。
- 一家公司数据不能被另一家公司结论借用。
- 追问与局部重做不重复解析已成功文档。

## 12. T8：历史恢复、不可变版本与导出

### 版本语义

- 分析中的工作区读取当前草稿。
- 已发布 artifact、引用、追问与导出使用明确发布版本。
- 历史旧版本仍能精确读取；不能因当前版本变化就跳转到不同数值。
- 导出某 revision 时必须使用该版本内容，不能先读取最新报告再忽略请求版本。
- 切换基准或取数政策生成新版本，保留旧版本。
- 来源文件不再可用时保留已保存数据并说明原件访问受限，不能误报仍可预览。

### 恢复语义

- `/runs/latest` 能返回当前会话的最近对比结果。
- `recoverFinancialHistory` 不再假定标题一定来自 `companyName`。
- 保留聊天历史 `protocol_version: 2`；它与报告数据 `schemaVersion: 2` 是独立协议。
- 只恢复真实保存内容，不补造丢失的用户消息或工具步骤。
- 公开快照不得泄露内部草稿、模型推理或其他任务数据。
- 刷新、重新打开和恢复不自动重跑模型。
- 进行中、已中断、数据就绪、已发布状态不互相冒充。

### 导出语义

- JSON 与 HTML 使用同一个所选版本的公开快照。
- 离线 React runtime 通过公共分发组件渲染单报告和对比报告。
- HTML 保留数据、图表、公式和证据摘录。
- 原件预览需要在线授权时，离线界面明确提示，不能保留无效按钮。
- 保留当前 HTML 数据注入转义和离线资源约束。
- 测试构建输出到隔离目录，不覆盖日常服务正在使用的 runtime。

### 验收

- 刷新和进程中断后已保存内容可恢复。
- 局部重做不丢失其他专题。
- 更新报告后旧版本的引用、追问和导出仍保持一致。
- HTML 离线打开时不依赖后端取数据。

Data Agent 能力全景

阿里把"数据智能体"拆成四大核心能力 + 数据集成垂直集，全链路覆盖 集成→开发→运维→治理→分析。新版 Data Agent 基于 Qwen Code 构建 —— 与你 DB-GPT 的 pi 引擎同源，Skills / 审批 / MCP 工具范式可直接借鉴。

四大核心能力

自动化🤖

Agent 智能体

LLM 规划+任务分解，调 MCP Server 工具执行。5 类专用 Agent，/ 唤起。

  • 数据集成 Agent
  • 数据开发 Agent（ETL 全流程）
  • 数据运维 Agent（诊断报告）
  • 数据地图 Agent（NL 找表+血缘）
  • 数据治理 Agent（自主式治理）
编码⌨️

代码编程助手

NL2SQL + SQL 补全（Tab 采纳）。SQL/Python 生成/改写/优化/纠错/注释/测试/解释。

  • 取数查询 · SQL 优化转换
  • 语法/函数查询 · 功能咨询
  • 注释生成 · SQL 解释
  • 一键纠错 · 上下文感知
  • 多模型切换
问数📊

ChatBI

扮演数据分析师，基于数据集提问，全流程自动化。

  • 问题理解 → 目标表识别
  • SQL 生成运行 → 图表绘制
  • 结论提炼（图文报告）
  • 知识库纠偏（模板/术语/逻辑）
  • 报告分享 HTML/PDF
内嵌⚡

快捷 AI 操作

模块内 Copilot 按钮，一键智能化产品操作。

  • 查询结果智能可视化
  • AI 智能建表（关键字→DDL）
  • 任务发布描述生成
  • 任务异常智能诊断
  • 质量规则推荐 · API 生成

DI Agent —— 数据集成垂直能力集（六大能力）

💬 对话式任务配置

单表/整库 × 离线/实时统一管理，一句话建任务，自动 Schema 探测+字段映射+调度。

🧠 AI 数据处理（多模态 ETL）

把大模型当 ETL 算子嵌入 Source→Transform→Sink，图片/视频/音频/文档识别打标转写向量化。

🗄️ ChatDB 数据问答

复用 80+ 连接器，业务语言即问即答 + 建库建表 + 表结构变更 + 慢 SQL 性能排查。

🩺 AI 诊断

聚合日志/监控/源端状态定位根因，给修复方案+一键执行，经验自动归档知识库。

🔁 智能周期巡检

Cron 主动扫描全量链路，出可下载报告，高风险按影响排序。

📱 IM 频道集成

钉钉/微信/飞书直接对话，完成状态查询、诊断、任务管理。

📌 范围判断：DB-GPT 定位"业务库智能取数+分析"，不做数据集成 ETL / 调度运维 / 质量治理。DI Agent 与数据运维/治理 Agent 属"定位差异"，非必须补齐 —— 火力应集中在 语义层 + ChatBI 问数闭环 + 审批/Skills 产品化。

🔑 生成机制（双维度交叉验证）：① 读"代码所在空间"的 SQL 脚本，从真实代码反提取口径（如发现 gmv = SUM(CASE WHEN order_status='paid' THEN pay_amount END)）；② 扫描重点表元数据（字段含义/同义词/层级/派生公式/示例问答）。官方强调"选对代码空间"是质量分水岭，否则只能靠字段注释猜。

加载前后对照（官方实验）

  

    
❌ 未加载语义模型

      
问："近 30 天各品类的客单价是多少？"


-- AI 不理解"客单价"口径，表名字段全猜错
SELECT category, AVG(price) AS avg_price
FROM products
GROUP BY category;

      
客单价 ≠ 商品均价；缺时间过滤；表名错误

    
✅ 已加载语义模型

      
同一问题，注入 metrics + metric_formulas 后：


-- 语义模型知道：客单价 = GMV / 订单数
SELECT cate_level1_name,
       SUM(gmv)/SUM(order_cnt) AS avg_order_value
FROM ads_ctlive_item_stats
WHERE stat_period = '30d'
GROUP BY cate_level1_name
ORDER BY avg_order_value DESC;

      
正确表名 · 正确口径 · 正确统计周期

  


  
🎯 对 DB-GPT 的启示：你现有 DBSummary 只做 schema 摘要注入，没有 metrics/metric_formulas/synonyms/few_shots 结构化语义模型。这与你既有定论完全一致 —— 结构化库=权威源，KB 托管空间=派生向量索引。建议 P0 落地 YAML 语义层，数据模型直接对齐阿里四模块（少走弯路、便于对标）。

给 DB-GPT 的三条判断

  

    
🔗
技术选型同源
阿里新版 = Qwen Code + Skills + 审批 + MCP，与你 pi 引擎几乎一致。这些不是"要不要做"，而是"把已有底座产品化"。

    
🧬
语义层是分水岭
阿里用整块功能证明问数地基是语义层，与你语义层定论一致。列 P0，数据模型直接对齐阿里四模块。

    
🎯
范围要克制
阿里是全链路平台，DB-GPT 聚焦取数+分析。集成/运维/治理属定位差异，不盲目补齐。

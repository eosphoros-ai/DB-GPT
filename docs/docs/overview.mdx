# Data agents for trusted, controlled data work

DB-GPT is an open-source Data Agent platform that turns business questions into queries, analysis, reports, and dashboards. It combines governed semantic definitions, reusable scenario plugins, agentic workflows, and controlled tool execution.

Our vision is to let teams delegate data work within explicit business and execution boundaries—and inspect the definitions, process, and evidence behind the result.

![DB-GPT home with its five official scenarios](/img/data-agent/en/home.png)

## Why this matters

A database schema tells an agent where a number lives; it rarely explains what that number means. “Revenue” may include freight in one team and exclude it in another. A join can multiply payment amounts without raising a SQL error. A polished report can hide missing evidence.

Long tasks add another problem: instructions alone do not reliably coordinate several agents. Work can drift from the plan, skip a step, or pass an unverified result downstream. Teams need reusable methods, visible responsibilities, and places to intervene.

## Four foundations

| Foundation | What it helps you do | Start here |
| --- | --- | --- |
| Governed semantics | Maintain business meanings and publish versioned metric definitions that agents can read and cite. | [Semantic Center](./semantic-center/overview.md) |
| Reusable scenario plugins | Select a task-specific package of skills, instructions, and tool configuration. | [Plugins](./plugins/overview.md) |
| Agentic Workflow | Give each agent a stage, responsibility, and deliverable; coordinate dependencies and add review gates. | [Agentic Workflow](./workflow/introduction.md) |
| Controlled execution | Configure data access, tool availability, approval policies, and execution environments; inspect actual tool results. | [Controlled execution](./data-agent/controlled-execution.md) |

“Trusted” means being able to check definition sources, metric versions, executed queries, and delivered artifacts. “Controlled” means making the available resources, tools, and review points explicit. These mechanisms support verification; they do not guarantee every generated calculation is correct.

## Choose your first scenario

The homepage exposes five official plugins:

- **Smart Data Query**: answer a bounded data question with SQL, results, and available metric references.
- **Smart Data Analysis**: investigate changes and deliver analysis, reports, or dashboards.
- **SQL Optimization Expert**: diagnose queries and propose rewrites or indexes with evidence and validation limits.
- **Metadata and Architecture Expert**: document physical schemas, build ER diagrams, and distinguish declared constraints from inferred relationships.
- **Financial Report Analysis**: analyze supplied financial reports with document, period, and unit references.

[Explore the scenarios and reproduction steps](./use_cases.mdx).

## From a question to a checkable result

1. Configure a working model and connect a database or attach the required files.
2. Prepare business definitions in Semantic Center when the task depends on a specific metric.
3. Choose a plugin on the homepage and state the scope, period, units, and expected deliverable.
4. For recurring complex work, use a Flow to separate grounding, fetching, analysis, review, and reporting.
5. Review any confirmation request and inspect the executed queries, result limits, and artifacts.

[Install DB-GPT](./getting-started/index.md), then follow [Your first data task](./data-agent/quickstart.md).

## What to expect today

Semantic tools read published business meanings and metric snapshots for the selected database. Keyword and alias search is available; automatic enforcement of every semantic rule is not. Plugin configuration is a method and capability declaration, whose runtime support must be checked. Flow exposes node status and failures; failure visibility is not a promise of checkpoint recovery.

The platform also provides developer building blocks: [custom workflow operators](./workflow/custom-operator.md), [RAG](./modules/rag.md), [multi-model management](./modules/smmf.md), and [execution harnesses](./harness/introduction.md). Use them to extend the product around your own data and operating requirements.

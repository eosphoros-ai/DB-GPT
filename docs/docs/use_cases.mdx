# Show Cases

DB-GPT helps teams turn data questions into SQL, code, charts, dashboards, reports, and
knowledge-driven workflows. Every scenario below was run end-to-end on the **pi harness
engine** against the bundled `Walmart_Sales` sample database; the screenshots are taken
from the live product UI in light theme.

## Scenario 1 — Natural-language fetching with first-class query artifacts

Ask a business question in plain language; the pi engine grounds itself in the schema
(table list, column stats), writes the SQL and executes it. Every result set arrives as a
**query artifact**: the executed statement in a copyable, editable SQL block, the result
table with row-count and truncation notes, and one-click CSV / Excel export.

![A pi-engine fetch turn: SQL block plus result table artifact with exports](/img/showcases/en/fig-01-fetch.png)

- Schema-grounding queries are artifacts too, so the whole reasoning chain stays
  inspectable after the turn ends.
- **Edit & re-run** lets you tweak the generated SQL and re-execute it in place; the
  re-run endpoint re-checks conversation and datasource ownership and enforces read-only
  SQL, so the convenience never widens the trust boundary.
- Result payloads travel capped for display (2000 rows) but exports always carry the full
  set.

## Scenario 2 — Autonomous profiling into a visual HTML report

One message ("profile this database and give me a visual report") lets the pi engine plan
its own probes — row counts, date ranges, top stores, concentration — and then render a
styled HTML analysis report through the HTML tool. The report lands as an **HTML
artifact**: a card in the conversation, a thumbnail in the artifact rail, and an in-place
preview panel.

![A pi-engine analysis turn with the HTML report open in the rail preview](/img/showcases/en/fig-02-report.png)

- Artifacts persist with the conversation: reload the page and the timeline, the trace
  and every artifact card rebuild identically.
- The Trace entry opens the synthesized span tree (thoughts, tool actions, terminate) for
  pi runs, so long autonomous turns stay auditable.
- High-risk tool calls in any scenario raise the same confirmation dock, with
  session/always memory keyed by class of call.

## Scenario 3 — Repeatable analysis as a declared workflow

When a analysis pattern recurs, promote it from ad-hoc chat to a **TaskFlow workflow**: a
declared DAG of focused agent nodes (grounding → fetch → pivot → numeric review →
report), each with its own tool boundary and output contract. Node runs reuse the same
harness contract, so workflow runs produce the same query artifacts, HTML reports and
traces as the scenarios above. See the [Workflow guide](../workflow/introduction.md).

## Pick your engine

All scenarios run on whichever harness engine you select — the built-in DB-GPT loop or
the external pi harness — with identical tools, approvals and artifacts. Engine choice,
availability and the extension contract live in the [Harness guide](../harness/introduction.md).

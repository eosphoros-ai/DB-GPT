# 流程编辑器

编辑器把模板变成你的 flow：左侧节点画布、右侧属性面板、头部部署控制。

![编辑器画布（DB 智能分析）](/img/workflow/zh/fig-06-editor-canvas.png)

## 画布基础

- **加节点**——从面板选 kind：智能节点一律 `agent`，另有 `start` / `output` 边界、
  `file_data` 数据面入口、`human_confirm` 确认门；
- **连线**——从节点输出柄拖到另一节点输入柄。边声明控制顺序；数据通道是隐式的（每个节点
  看得见所有在前节点的产出）；
- **删除/改名**——选中节点后用属性面板或删除键。

## 属性面板

点击节点编辑。agent 节点的面板就是它的能力边界：

![agent 节点属性面板](/img/workflow/zh/fig-07-node-panel.png)

| 字段 | 含义 |
|---|---|
| 标签 | 运行卡节点链上显示的名字 |
| Agent 画像 | 人设骨架：数据分析师 / 知识专家 / 通用执行者 |
| 目标 | 节点目标。**以一行 `输出:` 契约收尾**——下游节点依赖它 |
| 工具 | 勾选即边界：SQL、代码解释器、知识检索、HTML 渲染、Shell |
| 技能 | 挂载的技能包（附加 `load_skill` / 脚本工具） |
| 数据源 | `sql_query` 可碰的 connector；空 = 没有 SQL 工具 |
| 知识库 | `knowledge_retrieve` 与 `kb_*` 族的知识空间 |
| MCP | 行内 `sse:` / `http:` MCP 服务，仅本节点可见；连不上跳过不致命 |
| 最大回合 | 本节点 ReAct 循环上限（1–30）；全链预算建议 ≤40 |

goal 怎么写才利于组合，见 [agent 节点参考](./nodes/agent.md)。

## 校验、保存、部署

- **保存**写入 `developing` 状态——草稿，**不能**在对话里跑；
- **部署**把 DSL 编译为 AWEL DAG、注册并置为 `running`；只有 `running` 的 flow 可运行、并在
  服务重启后自动重新注册；
- 头部与模板中心/My Flows 列表都显示状态徽标。

:::tip
服务重启后 `running` flow 会自动重注册；重启后仍报 dag 找不到的，通常是停在 `developing`——
部署一次即可。
:::

## 实例与版本

内置模板首次在对话运行时实例化进 My Flows（按浏览器缓存）；编辑你的实例不会碰模板；模板的
创建参数变化会使旧缓存失效，下次使用自动重建新形态。

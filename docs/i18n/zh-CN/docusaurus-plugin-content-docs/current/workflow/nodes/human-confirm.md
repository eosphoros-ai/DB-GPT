# 确认门（`human_confirm`）

`human_confirm` 节点暂停运行，请人决策后链路才继续。它是工具审批 dock 在工作流层的对应物：
用在**阶段级**决策（范围、时间窗、是否纳入处置包），而不是单个工具调用。

## 配置

| 字段 | 含义 |
|---|---|
| `message` | 确认 dock 上展示的问题。概括上游产出了什么、继续意味着什么 |

## 运行时行为

- 节点启动时运行卡显示 *waiting*，输入框上方浮出 dock，含 message 与批准/拒绝动作；
- **批准**——节点原样输出上游内容，链路继续；
- **拒绝或超时**——节点失败，下游随之失败，运行卡把门标红；超时遵循 设置 → 工具审批 的
  审批策略 TTL；
- 决策与工具审批一同入审计（谁、何时、哪个会话）。

## 门放在哪

- **昂贵阶段之前**：例如接地/计划之后、十分钟分析链之前，让人确认问题清单；
- **处置包之前**：运维类 flow 产出变更建议（索引 DDL、参数调整），门让负责人挑选哪些进最终
  报告；
- **不要**用于例行检查——每个门都加时延与确认疲劳；优先更紧的节点契约与只读工具边界。

## 放置示例

```text
start → 健康巡检 → 根因分析 → 处置建议
      → human_confirm("哪些建议纳入报告?")
      → 巡检报告 → output
```

门的 message 要自带决策材料：引用上游异常清单，并注明拒绝将终止运行。

# Agent 节点

一个 `agent` 节点承担一项明确责任，使用独立记忆和对话上下文，读取用户问题及上游输出，不直接共享其他节点的内部工具轨迹。

| 配置 | 用途 |
| --- | --- |
| `agent_profile` | `react_data`、`react_knowledge` 或 `react_general` |
| `goal` | 节点目标，建议以 `Output:` 明确交付 |
| `tools` | 允许挂载的能力 |
| `skills` | 节点 Skill 与脚本资源 |
| `datasources` | SQL 和语义读取的数据库范围；空配置不提供 SQL 访问 |
| `knowledge` | 知识检索范围 |
| `mcp` | 节点外部工具服务 |
| `max_turns` | 1–30 轮执行预算 |
| `model` | 覆盖会话模型 |
| `parallel_group` | 为独立 Agent 分支设置受支持的并行分组 |

工具选择包含 SQL、代码、知识、HTML、Shell 及当前支持的语义元数据、业务定义、指标搜索和版本读取。以部署版本的编辑器和实际挂载结果为准。

## 写可交接的目标

语义节点先明确业务定义与缺失项，不提前回答完整问题；取数节点限制扫描并交付 SQL、结果和单位；复核节点独立计算，不能只重复上游 SQL；报告节点必须调用真实成果工具，不能把原始 JSON 当报告。

`Output:` 是提示契约，不自动验证字段结构、指标公式或证据完整性。需要时另设复核或确定性检查。

## 预算与失败

按阶段复杂度设置轮次，估算模型用量时计入每个并行分支。频繁耗尽时先检查重复调用、资源缺失与任务范围，再调整预算。工具参数截断可能触发重试，模型供应商鉴权、余额或连接失败应标记节点失败，不能写成完成分析。

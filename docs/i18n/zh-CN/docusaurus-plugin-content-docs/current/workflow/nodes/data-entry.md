# 数据入口节点（`file_data`）

`file_data` 是工作流的确定性数据面：解析上传的 CSV/Excel，带上行数上限加载，产出紧凑摘要
（文件 id、行数、列数），下游 agent 节点经数据通道收到它。

## 配置

| 字段 | 含义 |
|---|---|
| `file_name` | 上传文件的展示名 |
| `file_id` | 上传 id，解析到 taskflow 文件缓存 |
| `max_rows` | 加载帧的行数上限（保护上下文与算力） |

## 为什么它不是 agent

上传解析、编码嗅探、截断保护是机械活，确定性优于临场发挥：让 Agent"加载"文件可能幻造路径或
静默丢行。入口保持为算子，下游引用的摘要就与实载内容严格一致。Agent 之后用
`code` / `sql_query` 分析已解析的数据集，而不是重读原始文件。

## 数据库场景没有入口节点

数据库工作流不设入口节点：`agent` 节点直接绑 `datasources`，由接地节点自己画像（表清单、
行数、枚举取值、关联线索）。见 [agent 节点](./agent.md)。

## 已退役数据算子

| 退役 | 替代 |
|---|---|
| `db_query`（盲提取） | 带 `sql_query` 的接地 `agent` 节点 + 显式语义卡契约 |
| `visualize`（gpt-vis 文本仪表盘） | 图表进入报告节点的 HTML 产物 |

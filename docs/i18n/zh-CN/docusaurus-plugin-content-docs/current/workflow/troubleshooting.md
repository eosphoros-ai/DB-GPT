# 工作流排查

| 现象 | 处理 |
| --- | --- |
| 所有节点立即失败，提示 DAG 不存在 | 检查是否仅保存未发布；发布后再运行，重启后核对注册状态 |
| SQL 提示缺少或越界数据源 | 核对节点 `datasources`；主对话绑定不能替代节点资源 |
| 401/402/403/429 或余额错误 | 修复供应商鉴权、余额或配额后重跑，错误不算成果 |
| 参数缺失或截断重试频繁 | 缩小节点输出、减少原始行数，检查模型输出限制 |
| 报告仅有 JSON 或无 HTML | 检查成果工具是否实际成功，收紧报告范围与交付要求 |
| 模板编辑没有生效 | 修改自己的副本后发布；既有副本不会自动变成最新模板 |
| 历史工具详情不完整 | 检查保存记录的结构化标记，旧记录不能补造缺失证据 |

## 失败后如何继续

定位第一个失败节点，检查实际错误，修复资源、模型或目标；配置修改后保存并发布，再重新运行。SQL 编辑重跑只运行那条查询，不自动恢复下游。

不要假设成功阶段全部复用、刷新后继续连接活动流或自动检查点恢复。历史页面能展示不代表重新执行成功。

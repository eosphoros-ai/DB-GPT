# 产物契约与 Gate

每个 Agent 阶段都应交付下游可用的结果，并说明如何判断结果是否充分。

## 写清交付要求

```text
只使用配置的数据库。读取指定已发布指标版本，执行范围受限的只读 SQL，
对缺失证据明确说明。
Output: 指标 ID/版本；已执行 SQL；列与单位；汇总结果；
行数与截断限制；来源成果；未解决假设。
```

契约保持简短具体，同时包含证据与缺失项。上游输出受上下文预算限制，过大的原始结果会挤占关键交接信息。

| 检查 | 建立什么依据 | 限制 |
| --- | --- | --- |
| 提示产物要求 | 请求特定结构和完成条件 | 模型遵循不等于自动验证 |
| 复核 Agent | 独立比较或重算 | 可能重复同一错误，应要求独立依据 |
| 确定性工具检查 | 具体已实现属性的验证 | 只覆盖实际检查项 |
| 人工 Gate | 人对是否继续的决定 | 不验证每个数字，也不批准所有调用 |

只有检查确实执行且结果可查，才能称产物已通过该项验证。

## 放置人工 Gate

在已有决策材料的阶段后加入 `human_confirm`，配置消息说明范围和继续的影响。批准后上游内容传给下游；拒绝或超时停止阶段并阻止依赖工作。

适用于范围确认、耗时调查或是否纳入整改建议。单次高风险操作走[工具审批](../application/high_risk_tool_approval.md)。

## 设计异常输出

规定定义、数据或工具缺失时返回什么。结构化“无法继续”比虚构答案更容易复核。检查失败原因、修复资源或发布新版 Flow 后重新运行；不假设自动从成功检查点恢复。

# 打造可信、受控的 Data Agent

DB-GPT 是面向业务数据工作的开源 Data Agent 平台，将业务问题转化为查询、分析、报告与看板。它通过可治理的语义定义、可复用的场景插件、Agentic Workflow 和受控的工具执行，让团队能够委托 Agent 完成数据任务，并核验过程与结果。

我们的愿景是：让团队在明确的数据、业务口径和执行边界内使用 Agent，追溯结果依据、检查执行过程，并将有效的方法沉淀为可复用能力。

![首页的五个官方业务场景](/img/data-agent/zh-CN/home.png)

## 为什么需要这些能力

数据库结构能说明数字存在哪里，却不一定解释数字的业务含义。同一个“收入”可能包含不同的运费与退款口径；明细 JOIN 可能放大金额却不触发 SQL 错误；漂亮的报告也可能缺少可复核的依据。

长程任务还会放大协作问题：仅靠 Prompt 或 Skill 约定，多 Agent 容易偏离流程、遗漏任务、传递不可校验的结果，异常后也难以判断如何继续。团队需要可复用的方法、明确的阶段责任和可介入的检查点。

## 四个产品支柱

| 支柱 | 解决的问题 | 从这里开始 |
| --- | --- | --- |
| 可治理的语义 | 管理业务含义，发布 Agent 可读取和引用的指标版本 | [语义中心](./semantic-center/overview.md) |
| 可复用的场景插件 | 将方法、Skill 和工具配置组织为任务能力包 | [插件中心](./plugins/overview.md) |
| Agentic Workflow | 明确 Agent 的阶段、任务、产物和 Gate，组织复杂协作 | [Agentic Workflow](./workflow/introduction.md) |
| 受控的工具执行 | 配置数据、工具、审批和执行环境，检查真实调用结果 | [受控执行](./data-agent/controlled-execution.md) |

“可信”强调定义来源、指标版本、真实执行和交付证据；“受控”强调资源范围、工具边界和复核节点。这些机制帮助团队验证结果，不代表每个生成的计算都自动正确。

## 聚焦哪些场景

- **智能取数**：通过只读 SQL 回答范围明确的数据问题，交付结果和可用的指标引用。
- **智能分析**：解释业务变化，生成分析、报告或经营看板。
- **SQL 优化专家**：基于结构和计划证据提出诊断、改写与索引候选。
- **元数据与架构专家**：交付数据字典、物理 ER 和结构文档，区分声明约束与推断关系。
- **财报分析**：基于提供的报告文件分析财务信息，注明来源、期间和单位。

## 从问题到可核验交付

1. 配置可用模型，连接数据库或提供任务需要的文件。
2. 在语义中心准备业务定义，审核并发布指标口径。
3. 在首页选择插件，明确范围、期间、单位和交付物。
4. 对复杂或重复任务，用 Flow 分离语义与需求、取数、分析、复核和报告。
5. 查看确认请求、工具执行记录、结果限制与最终成果。

先[安装 DB-GPT](./getting-started/index.md)，再完成[第一次数据任务](./data-agent/quickstart.md)。

## 当前能力边界

语义工具按选定数据库读取已发布业务定义和指标快照，支持关键词与别名检索；不会自动强制所有语义规则。插件配置声明任务方法与能力，具体运行支持需要核对。Flow 展示节点状态和失败，异常可定位不等于自动断点恢复。

开发者还可以使用[自定义工作流算子](./workflow/custom-operator.md)、[RAG](./modules/rag.md)、[多模型管理](./modules/smmf.md)和[执行 Harness](./harness/introduction.md)扩展产品。

# 使用 LLM-Wiki 组织知识

LLM-Wiki 为知识空间增加便于阅读的资料组织层。它通过大语言模型将文档整理为摘要、概念或实体页面，并建立页面之间的链接。读者需要先了解一组资料的结构，再查找具体条款时，可以使用它。

例如，在指标治理场景中，Wiki 可以组织净实收定义、退款归属和相关术语。这些页面属于生成的解释，源文档仍是依据。

## 启用 Wiki 生成

创建[知识空间](/docs/getting-started/web-ui/knowledge-base)时，在**索引方式**中勾选 **LLM-Wiki 索引**。

![创建表单中的可选 LLM-Wiki 索引](/img/data-agent/zh-CN/knowledge-create.png)

截图展示该选项尚未勾选的状态。需要生成 Wiki 的空间应启用它，并检查表单提供的 Wiki 配置：

| 配置 | 用途 |
|---|---|
| 提取粒度 | 选择重点内容，或覆盖更详细的页面 |
| 生成模型 | 为生成任务选择可用模型 |
| 最大新增页面数 | 限制一批资料可能引入的新页面数量 |
| 内容指导 | 指定组织方式，例如“按业务概念组织，并保留来源引用” |

大规模导入前先检查模型是否可用。Wiki 生成会在文档处理之外增加模型调用；启用选项不代表生成任务一定成功。

## 生成与检查

上传或同步文档，并确认文档处理状态。启用了 Wiki 的空间可以在来源处理后进入增量生成队列。打开 **Wiki** 检查结果；需要生成或重建资料集合时，使用**生成 / 重建**。

![尚未生成页面的 Wiki 标签](/img/data-agent/zh-CN/knowledge-wiki.png)

截图展示中文界面中的空 Wiki。页面数为零，表示尚无可阅读的生成内容。出现 Wiki 标签或文档达到 `FINISHED`，都不能单独证明 Wiki 已生成成功。

重试空 Wiki 或失败任务前，检查源文档、所选模型、生成错误及服务端日志。额度或权限错误需要先解决模型访问问题。

## 浏览与复核页面

生成成功后，通过目录和搜索查找页面。**知识**与**摘要**视图帮助区分整理后的主题和文档摘要。查看页面的来源引用及反向链接，再沿链接阅读相关页面。

通过 **Wiki 图谱**探索生成页面之间的关系。它与 Markdown、代码图处理不同，也不代表已经核实实时数据库中的关系。

重要页面应逐项检查：

1. 定义与原文一致。
2. 例外规则及日期、版本限定没有丢失。
3. 相关页面没有引入互相冲突的规则。
4. 引用指向预期的来源资料。

内容缺失或错误时，先检查源文档。界面提供编辑与历史操作时，可以使用这些入口，并通过记录的版本比较或回退修改。重新生成可能产生新的解释，需要再次复核重要页面。

## 在 Agent 任务中使用 Wiki

为任务选择启用了 Wiki 的知识空间。具备 Wiki 工具的 Agent 可以通过 `kb_wiki_index`、`kb_wiki_search` 和 `kb_wiki_read_page` 浏览目录、搜索和读取页面。工具是否可用取决于所选空间与执行上下文。

可以提问：“梳理这个知识库中与净实收有关的概念，再引用退款归属的原始规则。”同时检查生成页面及原文引用。页面写入工具仅在受支持的上下文中提供；选择知识空间不代表一定拥有编辑能力。

需要精确原文支撑时，继续阅读[知识库问答](/docs/application/apps/chat_knowledge)。外部资料更新后，先检查[来源同步](/docs/getting-started/web-ui/external-datasources)，再重建 Wiki。

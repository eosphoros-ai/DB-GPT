# 知识库

知识库让 Agent 在回答问题时能够使用团队的资料。它适合制度查询、指标口径解释、产品手册问答和运维流程辅助，让回答有可供核验的来源。

在 DB-GPT 中，**知识空间**集中管理一组文档、处理配置、来源绑定和对话。**切片（chunk）**是为检索准备的文档片段。可选的 **LLM-Wiki** 会将资料整理成互相链接的页面，供用户浏览和 Agent 使用。

例如，把“净实收”的定义与退款归属规则放进知识空间，再让 Agent 根据原文解释这些规则。如果要从实时数据库记录计算净实收，还需要连接[数据源](/docs/modules/connections)，并在[语义中心](/docs/semantic-center/overview)中准备指标。

## 开始前准备

先准备一份答案明确的小文档，例如 Markdown 制度说明或运维手册。部署环境需要可用的文档处理后端；向量检索还需要 Embedding 模型和向量存储。问答与 Wiki 生成需要可用的大语言模型。相关服务尚未配置时，请参阅 [RAG 配置](/docs/application/advanced_tutorial/rag)。

本页截图使用中文产品界面，空间名称和文档描述保留创建时的语言。示例文档仍为 `TODO`、切片数为零，Wiki 尚无页面，对话尚无回答。这些截图展示当前操作入口，不代表导入或问答已经成功。

## 1. 创建知识空间

从侧边栏打开**知识库**，点击**创建知识库**。

![知识库列表](/img/data-agent/zh-CN/knowledge-list.png)

填写**知识库名称**与**描述**。名称可以使用 `Analytics_Governance`，支持中文、英文字母、数字、下划线和连字符。描述应说明资料范围和用途，例如：“电商分析使用的已审核指标定义及退款归属规则。”

![创建知识库、选择来源及索引方式](/img/data-agent/zh-CN/knowledge-create.png)

按资料来源选择类型：

| 来源 | 适用场景 |
|---|---|
| **文档** | 上传当前已安装加载器支持的 PDF、Word、Excel、PowerPoint、文本、Markdown 或 CSV |
| **Git Repository** | 导入仓库中的代码和文档，按需设置分支及包含、排除目录 |
| **文本** | 粘贴简短的定义或操作步骤 |
| **飞书知识库 / 语雀知识库 / RSS** | 绑定外部来源并选择需要同步的资料 |

当前选择器中的 Notion 卡片不可用。选择外部平台后，创建空间并继续完成[来源绑定流程](/docs/getting-started/web-ui/external-datasources)。Git 类型空间对应一个仓库；已导入后，通过同步操作更新该仓库。

### 选择处理方式

按部署环境实际配置选择索引：

| 界面选项 | 用途与前提 |
|---|---|
| **向量索引** | 语义检索，需要已配置的 Embedding 模型和向量存储 |
| **结构索引** | 当前界面对 `FullText` 选项的名称，需要已配置的全文检索后端 |
| **LLM-Wiki 索引** | 生成互相链接的 Wiki 页面，需要可用的大语言模型及成功处理的源文档 |
| **图索引** | 为受支持的 Markdown、代码内容进行额外图处理，请遵循表单中的格式提示 |

勾选多个选项不代表每种索引都已经构建。需要检查文档状态，并分别查看相应产物。**Wiki 图谱**展示 Wiki 页面之间的链接；**代码图谱**用于导入代码，两者是不同的视图。

需要调整切片时，展开**高级设置**。尽量保留完整的制度条款或操作步骤。可选策略与参数取决于来源及部署配置；创建表单中不提供 Embedding 模型选择。

文档类型选择文件后，点击**创建并上传**。建议先导入少量资料，核验完整链路后再扩大规模。

## 2. 添加文档并检查处理状态

打开知识空间的**文件视图**。左侧目录用于定位文档，右侧列表展示切片数量与处理状态。

![文件视图中的待处理文档](/img/data-agent/zh-CN/knowledge-files.png)

后续添加文件时，点击**添加数据源**，在添加文档弹窗中选择文件，再点击**上传并同步**。

![添加文档上传弹窗](/img/data-agent/zh-CN/knowledge-upload.png)

文件上传被接受与索引处理完成是两个阶段。点击**刷新状态**读取最新状态；通过文档操作菜单中的**同步**开始处理或重新处理。

| 状态 | 下一步 |
|---|---|
| `TODO` | 尚未完成处理，必要时发起同步 |
| `RUNNING` | 等待任务处理，再刷新状态 |
| `FINISHED` | 检查切片并测试检索；此状态不代表 Wiki 生成也已成功 |
| `FAILED` | 查看错误与服务端日志，修复原因后重新同步 |

打开已处理文档，检查可用的内容与切片，确认其中一段已知内容被正确提取。扫描 PDF 可能需要 OCR；上传成功并不代表其中的文字已经可读。

## 3. 提问并核验回答

进入空间的**对话**标签，确认选择的知识库与模型，提出一个能在资料中找到答案的问题。也可以在首页新建任务时选择知识库。

![知识空间内的对话入口](/img/data-agent/zh-CN/knowledge-chat.png)

以指标治理资料为例：

> 根据这个知识库，净实收是否包含运费？次月支付的退款应归属哪个月份？请引用原文，并指出资料中没有定义的规则。

将回答与返回的引用及原文逐项对照。回答流畅但缺少相关证据时，还不足以作为结论。如果资料没有定义某项规则，应让 Agent 明确指出缺口。可继续阅读[知识库问答](/docs/application/apps/chat_knowledge)中的核验清单。

## 4. 持续维护资料

| 视图或操作 | 用途 |
|---|---|
| **文件视图** | 检查文档、切片和状态，上传或同步文件 |
| **Arguments** | 查看空间的 Embedding / 检索、提示词及摘要配置 |
| **数据源** | 绑定外部平台，查看同步日志，暂停或恢复同步 |
| **Wiki / Wiki 图谱** | 有生成产物时，浏览页面及其关系 |
| **对话** | 围绕选中的知识空间提问 |
| **代码图谱** | 仓库图处理可用时，探索代码关系 |

在**数据源**标签中点击**绑定数据源**，进入连接器向导。来源同步、文档索引与 Wiki 生成是不同阶段，需要分别检查，不能仅凭拉取成功就认为所有视图已经就绪。

![数据源标签与绑定入口](/img/data-agent/zh-CN/knowledge-sources.png)

需要更易浏览的资料组织方式时，启用并使用 [LLM-Wiki](/docs/getting-started/web-ui/llm-wiki)。源文档仍是依据，使用生成的解释前需要复核。

删除文档或空间前，确认操作范围，并在 DB-GPT 之外保留原始资料。删除来源绑定会保留已同步文档；停用某个来源时，应另行检查这些文档。

## 常见问题

| 现象 | 下一步检查 |
|---|---|
| 上传成功但切片数一直为零 | 文档状态、加载器错误、文件内容以及是否发起同步 |
| 文档处理失败 | Embedding 服务、存储后端、文件格式及服务端日志 |
| 没有有用的引用 | 所选空间、已索引内容、问题中的术语及 Arguments 中的检索配置 |
| 回答与资料冲突 | 被引用片段、问题表述及不同版本资料之间的冲突 |
| 模型权限、额度或连接错误 | 修复所配置的模型服务；修改文档不能解决模型访问问题 |
| Wiki 或图谱为空 | 对应索引选项、文档处理状态、生成或图处理任务及其依赖 |

先让一份小文档产生可用切片，并得到有原文支撑的回答，再扩大资料集合。按业务范围组织相关内容，帮助 Agent 为不同任务选择合适的知识。

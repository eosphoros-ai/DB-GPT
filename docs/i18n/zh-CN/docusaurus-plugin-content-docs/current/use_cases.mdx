## 场景一——自然语言取数与一等取数产物

用业务语言直接提问；pi 引擎先接地 schema（表清单、字段统计），再写 SQL 执行。每个结果集
以**取数产物**形式到达：可复制、可编辑重跑的 SQL 块，带行数与截断说明的结果表，以及一键
CSV / Excel 导出。

![pi 引擎取数回合：SQL 块 + 结果表产物与导出入口](/img/showcases/zh/fig-01-fetch.png)

- schema 接地查询同样是产物，回合结束后整条推理链仍可检查。
- **编辑重跑**允许就地修改生成的 SQL 并重新执行；重跑端点复核会话与数据源所有权并强制
  只读 SQL，便利不扩大信任边界。
- 结果 payload 展示截断（2000 行），导出始终携带全量。

## 场景二——自主画像到可视化 HTML 报告

一句话（"画像这个库并给我可视化报告"）让 pi 引擎自主规划探针——总行数、日期范围、Top
门店、集中度——随后经 HTML 工具渲染出带样式的 HTML 分析报告。报告以 **HTML 产物** 落地：
会话内产物卡、rail 缩略图与就地预览面板。

![pi 引擎分析回合，HTML 报告在 rail 预览中打开](/img/showcases/zh/fig-02-report.png)

- 产物随会话持久化：刷新页面后时间线、轨迹与每张产物卡一致重建。
- Trace 入口打开 pi 回合的合成 span 树（思考、工具动作、terminate），长自主回合仍可审计。
- 任何场景中的高危工具调用都弹出同一确认 dock，session/always 记忆按调用类记忆。

## 场景三——把重复分析沉淀为声明式工作流

当分析模式重复出现，把它从即兴对话升级为 **TaskFlow 工作流**：声明式 DAG 的专注 agent
节点（接地 → 取数 → 透视 → 数字复核 → 报告），每个节点带自己的工具边界与输出契约。节点
运行复用同一 harness 契约，因此工作流产出与上述场景相同的取数产物、HTML 报告与轨迹。见
[工作流指南](../workflow/introduction.md)。

## 选择你的引擎

所有场景都可运行在你选择的 harness 引擎上——内置 DB-GPT 循环或外部 pi harness——工具、
审批与产物完全一致。引擎选择、可用性与扩展契约见
[Harness 指南](../harness/introduction.md)。

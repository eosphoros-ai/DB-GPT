# 专家套件：PI 与 DBGPT 实测对比

日期：2026-10-28。真实模型 `deepseek-v4-flash`，真实 SQLite 数据源 `Walmart_Sales`。两边使用相同自然语言任务、套件版本及命令。

结论：核心查询数据一致；两边均有真实 CSV、原生图表与 HTML 报告产物，但输出结构、报告质量与最终完成状态还不完全一致。

| 检查项 | DBGPT | PI |

| Top5 排名与销售额 | 20、4、14、13、2 | 相同，逐值 Decimal 比较通过 |
| CSV 文件 | 真实文件，3 列（额外包含 record_cnt） | 真实文件，2 列 |
| CSV 页面卡片、下载、刷新 | 通过 | 通过 |
| `db-analysis@1.1.0 /analyze` 技能与 SOP | 加载成功 | 加载成功，正文散列相同 |
| 原生图表与 HTML 报告 | 已生成 | 已生成 |

本轮补齐 PI 的原生 `chart_query`、`generate_report` 及证据捕获；两边接入 `export_csv`，读取当前执行结果导出文件，不重查、不调用 Shell。PI 保留完整文件、图表及报告输出用于历史回放，并过滤套件拒绝的工具。

另修复 PI 模型接口将原始用户问题移至工具结果之后的排序问题。消息顺序和推理/正文分离已有回归测试。修复后的最终真实模型复测（会话 `d1c75a79-0e14-4bc3-be7b-126faf064643`）在 3.12 秒直接收到 402 Insufficient Balance，未开始业务工具执行；因此该修复的完整真实模型流程尚未通过验证。已重启日常服务加载修复。

回归验证：产物、工具桥接、PI 流式和 SQL 工具共 38 项测试通过；模型接口 5 项测试通过。四组真实 Chrome 产物检查通过。

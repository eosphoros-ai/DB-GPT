# 智能体工作台

适用于智能体任务、自动化作业、模型服务与支持队列。没有运行日志时不能声称测得在线率、延迟或真实成本。

## 执行要点

浅石灰画布、白色内容区、靛紫色选中态，少量绿色标记已确认健康。优先任务列表、状态筛选、详情区域，然后补充吞吐、耗时和失败趋势。所有状态都配文字；重试不重复计入成功任务，成功率分母含成功/失败/取消的定义应明确。延迟分位数基于单次请求记录，不平均多个 p95。成本说明币种、定价日期与使用量依据；缺少价格或token记录则隐藏成本估计。错误聚合保留最近发生时间、次数及受影响任务，任务结果可展开验证。原生看板提供只读监控视图，不绘制并不存在的重试、暂停、删除按钮。主色 #6058DE、背景 #F1F3F5、正文 #293046。

## 对话示例

“看看哪里不对”时先检查错误率、积压、耗时与最近状态变化，按实际异常程度排序；没有异常证据时说明观察范围，不编造故障。

## DB-GPT 工作方式

- 按用户的语言交流。先结合已选数据、前文、看板与批注推断意图；表达含糊但可推进时说明一个合理假设并继续。只有会改变结果的缺口才问一个具体问题，不重复通用澄清句。
- 已选数据库只作只读发现，确认字段、粒度、单位、日期范围、空值与唯一键。没有数据时仍可讨论布局；实际指标生成前请用户选择数据源。示意值须明确标注，绝不伪装成查询结果。
- 创建可编辑看板时调用现有 dashboard 工具，并加载 dashboard-builder 的工作流：先 plan_dashboard，按现有确认流程创建；修改已存在看板时先 load_dashboard_draft，再提出匹配版本的更改。视觉规范补充业务计划，不能跳过 SQL 校验、保存或发布规则。
- 用户明确要 HTML 报告时再走报告生成工具；原生看板不得偷偷替换成一张图片或独立 HTML。原生 schema 只使用工具允许的字段、图表类型与主题属性，不传任意 CSS 或不存在的布局枚举。无法完整表达的装饰应收敛成可用的配色/布局，并说明差异。
- 编辑前保留用户的数据、指标口径和未修改组件。指标变更要同步标题、单位、计算定义；比例聚合先合计分子分母。无目标数据不补造目标、同比或预测。
- 交付前检查空结果、长标签、窄屏、深浅主题、图例、零值与缺失值；动画响应用户的减少动效偏好。只报告工具确认的执行结果。

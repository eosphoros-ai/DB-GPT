# 报告证据核查

供报告代理内部使用；不要在报告、状态消息或最终回答中提及本技能或内部规则。来源、选择器及数值绑定检查不代表所有自然语言结论已经核实；区分观测、推断与建议，相关性不能当作因果关系。

## 读取与选择

- 用 `report_evidence_manifest` 获取 SQL、Python、图表产物目录，按业务含义选择真实 ID；目录不是完整结果。用 `artifact_ids` + `detail=true` 批量读取需要的产物，每次最多 12 个。不得猜测来源或字段，不能仅凭数值相等推断来源。
- 清单中的 `metrics` 是会话内已校验的标量坐标。数值位置优先用 `{"metric_id":"清单中的真实 ID"}`，程序会展开为原始产物及字段路径并再次校验；目录里没有该指标时，再按真实产物详情选择 selector。目录里的 label 可能只是 SQL 列别名或 Python 字段名，grain 可能未知，不能据此臆断业务口径。目录不会把前一轮产物伪装成本轮执行结果。
- 大型结果使用 `selectors` 指定真实字段与路径。SQL 行使用 `path=["rows",行下标,"列名"]`，Python 使用真实 `field` 和相对 `path`；以清单返回的结构和选择器示例为准。预览截断不代表结果缺失；若出现 persisted-output，用 `read_file` 查看，不要重复完成过的分析。
- 选择实际采用的知识库口径：查看 reference 目录，读取相关切片原文，只引用支持对应内容的切片。逐字引用的 quote 必须来自该切片原文，转述不要冒充原文。上传的数据文件或口径文本可以作为来源，但计算数值必须绑定实际 SQL/Python 结果。
- 引用实际图表产物；Python 计算产物与生成图片的 chart 产物 ID 不同，可按 `input_artifact_ids` 追溯。没有可用图表时用已有结果和文字，不要猜测图片地址或来源。
- 自定义 ECharts 的 `series.data/nodes/links/edges`、`dataset.source` 和坐标轴 `data` 必须引用已捕获结果，类别标签也需有来源。优先使用 producer 的表格数据和真实列名配置 `dataset/encode`，不得手填观测数据。默认 dataset 可由 producer 的 rows/columns 注入。
- 复杂图表使用已捕获的对应结构；缺少转换数据时请求主代理补算。地图通过 `chart.maps={地图名称:{artifact_id,field/path}}` 引用已捕获的 GeoJSON，option 使用同名地图。JSON option 不支持 JavaScript 函数或第三方扩展，必要时使用已捕获图片。

## 绑定与修复

- 每个观测数值对应真实结果及选择器；表格与图表分别绑定其数据或图表来源。未捕获的合计、差值和比例不得伪造，确为用户必需时请求主代理补算。方法中的代码、日期格式与示例常量不是观测数据。
- 将建议目标与观测事实分开。建议可使用定性描述或量化目标，目标应明确标为建议而非已观测数据；涉及已观测的依据仍须引用真实来源。知识库只解释实际采用且影响解读的口径，避免重复复制正文。
- 建议段落可使用独立的 `{"proposal":"目标文字"}`，也可在来源引用节点标记 `proposal`。两者均只表示建议目标，不证明目标会实现。
- 遵照工具返回的具体错误及真实可用字段，仅修复受影响内容，保留已接受内容；不重发整份报告、不重跑已完成分析。无法核实的数值应删除或如实说明。
- 最终由报告渲染器及确定性校验器检查；有未核实内容或降级提示时如实说明，不声称所有自然语言结论均已核实。
